# Авито Очередь

MVP сервиса пользовательской очереди на дефицитные товары.
Пользователь встаёт в очередь перед чекаутом, получает временное
персональное право на покупку — система гарантирует, что одна единица
товара не уйдёт двум покупателям одновременно.

**Команда 33 «Dream Team»** · Avito Start, кейс 2

## Стек

- **Backend:** Go, chi, pgx, goose
- **Frontend:** в разработке
- **База данных:** PostgreSQL
- **Запуск:** Docker Compose + Go

## Быстрый старт

Требования: Docker, Docker Compose, Go 1.25+.

1. Поднять базу:
   ```
   docker compose up -d
   ```
2. Запустить приложение (миграции применяются автоматически при старте):
   ```
   go run ./cmd
   ```
3. Проверить:
   ```
   curl http://localhost:8080/health
   ```

## Структура

```
/cmd                     — точка входа
/internal
  /app                   — сборка зависимостей, подключение к БД и миграции, старт/остановка приложения
  /config                — чтение конфигурации (viper)
  /infra
    /http/rest           — HTTP-сервер (chi): сервер, роутер, хендлеры
    /postgres/repository — Будущие репозитории, вся работа с базой
/migrations              — goose-миграции
/configs                 — configuration.yaml
/docs                    — REQUIREMENTS.md
```

## Линтеры

Backend: golangci-lint. Конфиг: `.golangci.yaml` в корне.

Включённый набор и почему:
- `govet`, `staticcheck`, `unused`, `ineffassign` — базовая гигиена кода, мёртвый код и типичные баги.
- `errcheck` — в Go легко случайно проигнорировать ошибку; для сервиса, где корректность важнее скорости, это недопустимо.
- `rowserrcheck`, `sqlclosecheck` — специфичны для работы с БД через pgx/database/sql: ловят незакрытые `*sql.Rows` и непроверенные ошибки после итерации, частый источник утечек соединений.
- `noctx` — требует явной передачи `context.Context` в HTTP- и SQL-вызовы, что нужно для корректного graceful shutdown и таймаутов.

Проверить линтеры локально:
```
golangci-lint run
```
